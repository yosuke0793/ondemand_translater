# macOSインストール手順（初心者向け）

[ユーザーガイドへ戻る](USER_GUIDE.md) · [Windows用手順](INSTALL_WINDOWS.md) · [困った場合](TROUBLESHOOTING.md)

**初心者向け同梱版のDMGが公開されている場合は、[同梱版のインストール手順](INSTALL_BUNDLED.md)をおすすめします。** 同梱版はHomebrew・Python・プロジェクト取得不要で、APIキーも画面から保存します。

以下は**ソースコードからのインストール**用です。従来方式も利用できます。コマンドは1つの枠ごとにコピーし、「ターミナル」に貼り付けてReturnキーを押します。処理が終わるまで次へ進まないでください。

## 1. 用意するもの

- Apple Silicon（Mシリーズ）またはIntel搭載のMac
- インターネット接続、十分な空き容量、電源
- ソフトウェアの導入を許可されたアカウント
- HomebrewとXcode Command Line Tools（以下の手順で準備）
- Geminiを使う場合はGoogleアカウントとGemini APIキー

Appleメニューの「このMacについて」で、MシリーズかIntelか確認できます。アプリは実行したMac用に生成します。他のMacで作った `.venv` やアプリを持ち込むのではなく、各Macでインストールしてください。Rosettaで起動したターミナルではなく、そのMac標準のターミナルを使うことを推奨します。

macOSの最低バージョンや最低メモリ量は、このプロジェクトでは数値で保証していません。Homebrewや依存ライブラリが対応するOSが必要です。古いmacOSで失敗する場合は担当者に確認してください。

社用・学校用のMacでは導入に管理者の承認が必要な場合があります。管理者制限を解除する操作を独断で行わないでください。

## 2. ターミナルの開き方

1. キーボードのCommandキーを押しながらスペースキーを押します。
2. 「ターミナル」と入力します。
3. 「ターミナル」アプリを開きます。
4. 文字入力できる画面が表示されます。

コマンドの枠だけをコピーします。説明文や、画面に表示される `%`、`$` などの入力待ち記号はコピーしません。Command + Vで貼り付けます。

パスに空白がある場合は引用符が必要です。後の手順ではFinderからフォルダーをターミナルへドラッグする方法も案内します。

## 3. 開発用ツールとHomebrewを用意する

### 3-1. Xcode Command Line Tools

ターミナルで実行します。

```bash
xcode-select --install
```

インストール画面が表示されたら案内に従って完了させます。既にインストール済みという表示なら次へ進みます。アプリの生成に必要な `clang` などが含まれます。大きなXcodeアプリ全体を導入する必要はありません。

確認します。

```bash
xcode-select -p
```

ツールの場所が表示されれば確認完了です。エラーの場合は[トラブルシューティング](TROUBLESHOOTING.md)へ進みます。

### 3-2. Homebrew

Homebrewは、アプリに必要なPythonやFFmpegを導入する道具です。

1. ブラウザで[Homebrew公式サイト](https://brew.sh/)を開きます。
2. 公式サイトの「インストール」欄に掲載されたコマンドをコピーします。検索広告や第三者サイトのコマンドは使わないでください。
3. ターミナルへ貼り付け、Returnキーを押します。
4. 内容を確認し、画面の案内に従います。
5. Macのログインパスワードを求められたら入力してReturnキーを押します。**入力しても文字や●は表示されません。**
6. 最後の「Next steps」に表示される設定コマンドがあれば、そのMac向けの内容を実行します。
7. ターミナルを閉じ、新しく開き直します。

確認します。

```bash
brew --version
```

`Homebrew` とバージョンが表示されれば成功です。`command not found` なら公式サイトの手順と「Next steps」の設定を確認します。Translate ServiceのインストーラーはHomebrew自体をインストールしません。

## 4. アプリのファイルを取得する

### 方法A：ZIPをダウンロードする（初めての人向け）

1. ブラウザで[プロジェクトのGitHubページ](https://github.com/yosuke0793/ondemand_translater)を開きます。アクセスできない場合は担当者へ取得方法を確認してください。
2. 「Code」→「Download ZIP」を選びます。
3. Finderで「ダウンロード」を開きます。
4. ダウンロードしたZIPをダブルクリックして展開します。
5. 展開したフォルダーには通常 `-main` などの枝名が付きます。管理しやすいよう、名前を `ondemand_translater` に変更します。
6. フォルダーをホームフォルダーなど、今後も使う場所へ移動します。ここではホーム直下の `ondemand_translater` として説明します。
7. 中に `mac`、`win`、`source`、READMEがあることを確認します。

ホームフォルダーはFinderの「移動」→「ホーム」で開けます。**ZIPの中のファイルだけを起動せず、必ず全体を展開します。** 古い同名フォルダーがある場合は上書きせず、別の名前で保管してください。

### 方法B：Gitを使う（Gitを使える人向け）

以下はホーム直下へ取得します。既に同名フォルダーがある場合は実行せず、別の場所を選びます。

```bash
cd ~
git clone https://github.com/yosuke0793/ondemand_translater.git
```

SSHキーは不要です。取得できない場合は方法Aを使うか担当者に確認します。

## 5. インストーラーを実行する

1. Finderで取得した `ondemand_translater` フォルダーを開きます。
2. `mac` フォルダーを開きます。
3. `install.command` をダブルクリックします。
4. ターミナルが開き、セットアップの表示が流れます。
5. ダウンロード・依存ライブラリ導入・アプリ生成が終わるまで待ちます。
6. 最後に `Installation complete:` とアプリの場所が表示され、「インストールが完了しました。Enterキーで終了します。」と表示されたらReturnキーを押します。

### 自動で準備されるもの

- FFmpeg（なければHomebrewから `ffmpeg-full` を導入）
- Python 3.10～3.13の中から使用可能なもの。なければ3.12、次に3.10の導入を試行
- GUI用のTkinter（必要に応じて対応する `python-tk` を導入）
- このアプリ専用の `source/worker/.venv`
- Pythonライブラリ
- `mac/TranslateService.app`

初回は通信量が多く、時間がかかる場合があります。表示が止まっただけで何度も起動し直さないでください。終了前に `ERROR` やエラーが出た場合は成功扱いにせず、最後の表示を控えて[トラブルシューティング](TROUBLESHOOTING.md)へ進みます。

### ダブルクリックで実行できない場合

自分で公式プロジェクトから取得したことを確認してから、ターミナルで実行できます。ホーム直下へ取得した場合：

```bash
cd "$HOME/ondemand_translater"
bash mac/install.command
```

別の場所へ置いた場合は、ターミナルで `cd ` と入力し（末尾に半角スペース）、Finderのプロジェクトフォルダーを画面へドラッグしてReturnキーを押します。その後 `bash mac/install.command` を実行します。

macOSのセキュリティ警告については[トラブルシューティング](TROUBLESHOOTING.md)を参照してください。Gatekeeper全体を無効化する必要はありません。

**アプリだけを「アプリケーション」フォルダーへ移動しないでください。** このアプリは隣接するプロジェクトの `source/worker` を利用します。元の `mac` フォルダー内に置いたまま使います。

## 6. Gemini APIキーを設定する

### 6-1. キーを用意する

Gemini APIキーは、このアプリがGoogleのGeminiを呼び出すときに使う秘密の文字列です。Googleアカウントや大学・会社のログインパスワードとは別です。Google AI Studioは、そのキーを作成・管理するGoogleのWebサイトです。

1. ブラウザで[Google AI StudioのAPIキー画面](https://aistudio.google.com/apikey?hl=ja)を開きます。検索は不要です。公式の説明は[Gemini APIキーの日本語ガイド](https://ai.google.dev/gemini-api/docs/api-key?hl=ja)です。
2. 利用を許可されたGoogleアカウントでログインします。大学・会社のアカウントが使えるか不明なら担当者へ確認します。
3. 初回の利用規約等が出たら確認します。利用可能モデル、料金、割り当ても確認します。
4. APIキー一覧を確認します。初回利用時にはプロジェクトとキーが自動作成される場合があります。既に利用可能なキーがあれば、それを使えます。
5. 新しく用意する場合は「APIキーを作成（Create API key）」などのボタンを選び、画面に従って使用するプロジェクトを選択します。プロジェクトはGoogle側の料金・利用量・権限を管理する単位で、PC上のアプリフォルダーではありません。
6. キーのコピー操作で**キーの文字列**をコピーし、次の手順6-2の引用符内へ入れます。キーの名前やプロジェクト名ではありません。

作成ボタンが使えない、プロジェクトがない、権限がない場合は[APIキーを取得できない場合](TROUBLESHOOTING.md#gemini-apiキーの取得画面で進めない)を確認してください。具体的な画面名は提供元の変更により異なることがあります。

APIキーはパスワードと同様の秘密です。人に送るスクリーンショット、問い合わせ、GitHubへの投稿に含めないでください。

### 6-2. Finderから起動するアプリへキーを渡す

更新版GUIでは「APIキー設定」からキーチェーンへ保存する方法も使えます。[画面からの登録](INSTALL_BUNDLED.md#4-apiキーを画面から登録する)を参照してください。以下は環境変数で設定する従来方式で、環境変数のキーは保存済みキーより優先されます。

ターミナルで次を実行します。引用符内の `ここに取得したAPIキー` を実際のキーへ置き換えます。引用符は半角の `"` のまま残し、前後に空白や改行を入れません。

```bash
launchctl setenv GEMINI_API_KEY "ここに取得したAPIキー"
```

何も表示されなくても正常です。キーを表示する確認コマンドは不要です。既にアプリを起動している場合は一度終了し、開き直してください。

**この設定は永続保存を保証しません。Macの再起動・ログアウト後は、起動前に同じコマンドを再実行してください。** アプリの設定ファイルにキーを保存する機能はありません。

ターミナルで `export GEMINI_API_KEY=...` を設定するだけでは、Finderから起動するアプリへ伝わりません。Finder起動には上記の `launchctl setenv` を使います。

キーを含むコマンドはターミナルの履歴に残る可能性があります。共有PCでの入力や画面共有中の操作は避けます。

## 7. 起動と初回確認

1. Finderでプロジェクトの `mac` フォルダーを開きます。
2. `TranslateService.app` をダブルクリックします。
3. 「Translate Service」という画面が表示されることを確認します。
4. [ユーザーガイドの初回処理](USER_GUIDE.md#3-初めての動画を処理する)に従い、短いMP4を処理します。
5. 100%・完了になり、出力先に動画と字幕ができたことを確認します。

初回処理時は文字起こしモデルの取得があります。インストーラーが終わった時点で、すべてのモデルがダウンロード済みとは限りません。

起動しない場合は、プロジェクトの `source/worker/data/app-launch.log` をテキストエディット等で開き、[起動トラブル](TROUBLESHOOTING.md)を確認します。

## 8. 次回以降の起動・設定変更

- 同じ `mac/TranslateService.app` から起動します。毎回インストーラーを実行する必要はありません。
- Dockへ置く場合も、元のアプリ・プロジェクトフォルダーは移動しないでください。
- Macの再起動・ログアウト後はAPIキーを再設定します。
- APIキーを変えたら、アプリを終了して新しいキーを設定し、起動し直します。
- キーが不要になったら、アプリを終了して次でユーザーセッションの設定を解除します。

```bash
launchctl unsetenv GEMINI_API_KEY
```

提供元でキーを無効にする操作は、Google側の管理画面で別途行います。

ターミナルから起動する方法は[開発者ガイド](DEVELOPER_GUIDE.md)を参照してください。Finder起動とターミナル起動では標準のデータ保存場所が異なるため、切り替えると履歴が空に見える場合があります。
