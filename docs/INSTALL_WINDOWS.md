# Windowsインストール手順（初心者向け）

[ユーザーガイドへ戻る](USER_GUIDE.md) · [macOS用手順](INSTALL_MAC.md) · [困った場合](TROUBLESHOOTING.md)

**初心者向け同梱版のセットアップが公開されている場合は、[同梱版のインストール手順](INSTALL_BUNDLED.md)をおすすめします。** Python・winget・Gitの準備は不要で、APIキーもアプリの画面から登録します。

以下はWindows 11 x64向けの**ソースコードからのインストール**手順です。従来方式も利用できます。

## 1. PCと必要なものを確認する

1. 「スタート」→「設定」→「システム」→「バージョン情報」を開きます。
2. 「Windowsの仕様」のエディション・バージョンを確認します。
3. 「デバイスの仕様」の「システムの種類」を確認します。

想定する環境は**Windows 11 24H2 / 25H2、x64ベースのプロセッサ**です。インストーラーのチェックはWindows 11（ビルド22000以上）と64-bit OSですが、これは全バージョン・全CPUでの動作確認を意味しません。Windows 10、32-bit Windows、ARMベースのPCは対象外です。

ほかに次を用意します。

- インターネット接続、十分な空き容量、電源
- Microsoft Storeの「アプリ インストーラー（App Installer）」
- Geminiを使う場合はGoogleアカウントとGemini APIキー
- ソフトウェアの導入を許可されたユーザーアカウント

社用・学校用PCでは管理者の承認が必要な場合があります。管理者権限やセキュリティ設定の制限を無断で解除しないでください。

### 準備するものの意味と、検索せずに進める順番

| 名前 | 何のためのものか | 入手・準備する場所 |
|---|---|---|
| Gemini APIキー | このアプリからGoogleの翻訳処理を利用するための秘密の文字列 | [手順5](#5-gemini-apiキーを設定する)のGoogle AI Studio |
| winget（ウィンゲット） | PythonやFFmpegを導入する道具 | [手順2](#2-app-installerとwingetを確認する)のMicrosoft Store |
| PowerShell（パワーシェル） | 文字で指示を入力するWindowsの操作画面 | Windowsに含まれます。別途ダウンロード不要 |
| Git（ギット） | プロジェクトのファイル取得・更新に使う道具 | **ZIPで取得するなら不要**。[手順3](#3-アプリのファイルを取得する)の方法Aを推奨 |

まず手順2でwingetを確認し、手順3のZIP取得、手順4のインストール、手順5のAPIキー設定の順に進みます。PythonやFFmpegを個別に探して導入する必要は通常ありません。

## 2. App Installerとwingetを確認する

`winget` はPythonやFFmpegを自動導入するWindowsの道具です。「アプリ インストーラー」に含まれるため、winget単体のインストーラーを検索する必要はありません。

1. Microsoft Storeを開きます。
2. 「アプリ インストーラー」または「App Installer」で検索します。
3. **Microsoft Corporationが提供するもの**をインストールまたは更新します。
4. 詳細を確認したい場合は[Microsoftの日本語winget公式案内](https://learn.microsoft.com/ja-jp/windows/package-manager/winget/)を参照できます。通常はこのマニュアルの手順を進めればよく、公式案内内の開発者向け手順をすべて実行する必要はありません。
5. 「スタート」を開き、「PowerShell」と入力します。
6. 「Windows PowerShell」を開きます。最初から「管理者として実行」にする必要はありません。
7. 次を貼り付け、Enterキーを押します。

```powershell
winget --version
```

PowerShellは、PCへ文字で指示するための画面です。背景の色は環境によって異なります。`PS C:\Users\...>` などの文字の後ろに入力できます。上の枠の `winget --version` だけをコピーし、PowerShellの入力位置でCtrl + Vを押してEnterを押します。`PS C:\...>` は入力しません。確認が終わったら右上の「×」で閉じて構いません。

`v` で始まるバージョンが表示されれば確認完了です。「認識されません」などの場合は、PowerShellを閉じて開き直します。それでも認識されなければ一度サインアウト・サインインするか、[トラブルシューティング](TROUBLESHOOTING.md)を確認します。

Microsoft Storeを使えない管理PCでは、担当者へ相談してください。非公式サイトから実行ファイルを入手しないでください。

## 3. アプリのファイルを取得する

### 方法A：ZIPをダウンロードする（初めての人向け）

1. ブラウザで[プロジェクトのGitHubページ](https://github.com/yosuke0793/ondemand_translater)を開きます。アクセスできない場合は担当者へ確認します。
2. 「Code」→「Download ZIP」を選びます。
3. エクスプローラーで「ダウンロード」を開きます。
4. ダウンロードしたZIPを右クリックし、「すべて展開...」を選びます。
5. 「展開」を押して、通常のフォルダーへ取り出します。**ZIPを開いた状態から直接インストーラーを実行しないでください。**
6. 展開先を開き、`mac`、`win`、`source`、READMEが入ったプロジェクトフォルダーを確認します。ZIP名のフォルダーの内側にもう1階層ある場合があります。
7. `-main` などの付いたフォルダー名を `ondemand_translater` に変更し、今後も使う場所へ移動します。

以降は、ユーザーフォルダー直下の `ondemand_translater` に置いた例で説明します。エクスプローラーのアドレス欄へ `%USERPROFILE%` を入力してEnterを押すとユーザーフォルダーを開けます。既に同名フォルダーがある場合は置き換えず、別名で保管します。

初回はPC内の書込み可能な場所を選びます。`Program Files`、ネットワークドライブ、クラウド同期フォルダーは避けると権限・同期問題の切り分けが簡単です。

拡張子が見えない場合は、エクスプローラーの「表示」→「表示」→「ファイル名拡張子」をオンにします。Windowsの更新によってメニュー名が多少異なる場合があります。

### 方法B：Gitを使う（Gitを使える人向け）

**方法AでZIPを取得できた人は、この項目を飛ばして手順4へ進んでください。Gitを追加導入する必要はありません。**

Gitはファイルの変更履歴を管理し、プロジェクトを取得・更新する道具です。使いたい場合の公式入手先は[Git for Windows](https://gitforwindows.org/)です。組織の導入ルールを確認してから公式インストーラーを実行し、完了後に新しく開いたPowerShellで確認します。

```powershell
git --version
```

`git version ...` と表示されれば使えます。Gitが導入済みならPowerShellで次を実行できます。

```powershell
cd $HOME
git clone https://github.com/yosuke0793/ondemand_translater.git
```

Gitがない場合は方法Aを使えば構いません。ZIP取得にGitは不要です。

## 4. インストーラーを実行する

> **最初の1回で「失敗」と出ても、ここで諦める必要はありません。** PythonやFFmpegの導入直後に「新しいPowerShellを開いて再実行してください」と表示されることがあります。そのメッセージの場合は、下の[初回失敗時の手順](#初回に新しいpowershellを開いて再実行と出た場合)で1回再試行します。すべてのエラーが再実行だけで直るわけではありません。

1. エクスプローラーで取得した `ondemand_translater` フォルダーを開きます。
2. `win` フォルダーを開きます。
3. `install.cmd` をダブルクリックします。拡張子を隠している場合、名前が「install」だけに見えることがあります。
4. コマンド画面が開き、準備の表示が流れます。
5. OSから導入の許可を求められたら、公式プロジェクトの処理であることと表示内容を確認します。組織の承認が必要なら担当者へ相談します。
6. ダウンロード・依存ライブラリ導入・exe生成が終わるまで待ちます。
7. `Installation complete. Desktop shortcut created:` と、最後の `Installation completed. Press any key to close.` が表示されたら、何かキーを押して閉じます。

`Installation failed` は「インストールに失敗しました」という意味です。完了ではありませんが、直前の赤い文字に再試行の案内があれば、以下の手順へ進みます。赤文字というだけでPCが壊れたという意味ではありません。

### 初回に「新しいPowerShellを開いて再実行」と出た場合

FFmpeg導入直後、または以前の版のインストーラーでは、次の表示が出る場合があります。**更新版のPython検出は、PATH以外の導入先も調べます。Pythonが混在している場合は、再試行だけでなく下の[Pythonの自動検出と仮想環境の修復](#pythonの自動検出と仮想環境の修復)も確認してください。**

```text
Python 3.12 or 3.10 could not be found after installation. Open a new PowerShell and run install.ps1 again.
FFmpeg was not found after installation. Open a new PowerShell and run install.ps1 again.
```

意味は「導入後のPython／FFmpegを今の画面から見つけられません。新しい画面でインストーラーを実行し直してください」です。入れたばかりのソフトの場所が、今開いている画面にまだ反映されていない可能性があります。

1. 最後のエラーをメモするか、APIキー等の秘密情報が写らないように画面を撮ります。
2. `Press any key to close`（何かキーを押して閉じる）が出ていれば、キーを押して失敗したインストーラー画面を閉じます。ほかに開いているPowerShellも閉じます。
3. エクスプローラーで、先ほど使った**同じフォルダーの `win\install.cmd`** をもう一度ダブルクリックします。これで新しいPowerShellが自動的に起動するため、通常は手動で別のPowerShellを開く必要はありません。
4. 再度最後まで待ち、`Installation completed. Press any key to close.` とデスクトップのショートカットを確認します。表示の意味は「インストール完了。何かキーを押して閉じる」です。
5. 2回目も失敗した場合や、最初から別のエラーだった場合は[トラブルシューティング](TROUBLESHOOTING.md#windowspythonやffmpegを入れたのに見つからない)へ進みます。成功メッセージがない状態で手順5以降へ進まないでください。

同じインストーラーは既存の環境を利用しながら準備を続けます。再試行のために取得したフォルダーを削除したり、ZIPを取り直したりする必要は通常ありません。

### 自動で準備されるもの

- Python Launcher、Windowsの登録情報、標準導入先、PATHから使えるx64 Pythonを検出。新規環境は3.12を優先し、3.13、3.11、3.10の順に選択。なければwingetで3.12、次に3.10の導入を試行
- FFmpeg（なければ `Gyan.FFmpeg.Shared` をwingetで導入）
- アプリ専用の `source\worker\.venv`
- PythonライブラリとPyInstaller
- `win\dist\TranslateService\TranslateService.exe`
- デスクトップの「Translate Service」ショートカット

FFmpegを新しく入れた直後は、開いている画面が新しい設定を読み取れずエラーになることがあります。その場合はPowerShell・インストーラー画面を閉じ、**同じ `install.cmd` をもう一度実行**します。何度も同時に実行しないでください。

### Pythonの自動検出と仮想環境の修復

更新版のインストーラーは、`python --version` の結果だけでは判断しません。古いPythonが優先されていても、別に導入された対応版を探します。**他のアプリ用のPythonを削除したり、PC全体のPATHを変更したりする必要は通常ありません。**

- 選んだPythonの場所とバージョンを画面に表示します。
- x64、Python 3.10～3.13、Tkinter、仮想環境作成機能を実際に確認します。
- 既存の `.venv` が正常なら、その対応バージョンを維持して再利用します。3.10の正常な環境を、理由なく3.12に置き換えることはありません。
- `.venv` が非対応・破損・別の場所由来、またはpipが使えない場合は、**元の環境を `.venv.backup-日時-識別子` へ退避**して作り直します。
- 元の動画、出力、ジョブ履歴、設定、用語は削除しません。ただしインストール前にアプリと変換処理を停止してください。使用中の環境は退避できないことがあります。
- 仮想環境作成、ライブラリ導入、ビルド、依存関係検証で失敗した場合は、その場で停止し、成功メッセージを出しません。

`[python] Rejected` は「この候補は使わない」、`Usable` は「検証に合格した候補」、`Selected Python` は「新しく作る環境に採用するPython」です。古いPythonの候補が拒否されても、別の候補が採用されれば問題ありません。

自動検出できない場合は、担当者がPythonの実際の場所を確認し、`install.ps1` の `-PythonPath` で明示できます。[混在環境の確認手順](TROUBLESHOOTING.md#windowspythonが複数あり対応版を検出できない)を参照してください。退避フォルダーは新環境の動作確認後に、不要なら担当者がそのフォルダーだけを整理します。

### PowerShellから実行したい場合

ユーザーフォルダー直下へ取得した例：

```powershell
cd "$HOME\ondemand_translater"
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\win\install.ps1
```

これはこの1回のPowerShell実行に対する指定です。PC全体の実行ポリシーを恒久的に変更する必要はありません。組織のポリシーにより拒否される場合は担当者へ相談します。

SmartScreenなどの警告では、取得元と内容を確認してください。ウイルス対策やSmartScreen全体を無効化しないでください。

## 5. Gemini APIキーを設定する

### 5-1. キーを用意する

Gemini APIキーは、このアプリがGoogleのGeminiを呼び出すときに使う、利用者を認証するための秘密の文字列です。**Googleアカウントのパスワードでも、大学・会社のログインパスワードでもありません。** Google AI Studioは、そのキーを作成・管理するGoogleのWebサイトです。

1. 検索する代わりに、[Google AI StudioのAPIキー画面](https://aistudio.google.com/apikey?hl=ja)を開きます。公式の説明は[Gemini APIキーの日本語ガイド](https://ai.google.dev/gemini-api/docs/api-key?hl=ja)です。
2. 利用を許可されたGoogleアカウントでログインします。大学・会社のアカウントを使う場合、利用可能か担当者へ確認してください。「大学名 Gemini APIキー」で検索して出たページを順に試す必要はありません。
3. 初回の利用規約等が表示されたら内容を確認します。料金、モデルの利用可否、割り当ても確認し、分からない場合は担当者へ相談します。
4. APIキー一覧を確認します。初回利用者にはプロジェクトとキーが自動作成される場合があります。既に利用可能なキーがあれば、不必要に作り直す必要はありません。
5. 新しく用意する場合は「APIキーを作成（Create API key）」などのボタンを選び、画面に従って使用するプロジェクトを選択します。プロジェクトとは、Google側で利用量・料金・権限をまとめて管理する単位です。このアプリのダウンロードフォルダーとは別です。
6. キーが表示されたら、その項目のコピー操作で**キーの文字列**をコピーします。キーの名前やプロジェクト名ではありません。次の手順5-2の「変数値」へ貼り付けます。チャットや共有文書へ貼り付けないでください。

ボタンやプロジェクトが出ない、作成権限がない、利用が制限される場合は、[APIキーを取得できない場合](TROUBLESHOOTING.md#gemini-apiキーの取得画面で進めない)を確認します。画面名は変更される場合があります。

キーは秘密情報です。問い合わせや画面共有に載せないでください。

### 5-2. Windowsの画面で設定する（推奨）

更新版GUIでは「APIキー設定」からOSの資格情報マネージャーへ保存する方法も使えます。[画面からの登録](INSTALL_BUNDLED.md#4-apiキーを画面から登録する)を参照してください。以下はWindowsの環境変数で設定する従来方式で、環境変数のキーは保存済みキーより優先されます。

1. 「スタート」の検索に「環境変数」と入力します。
2. 「システム環境変数の編集」を開きます。
3. 「環境変数...」を押します。
4. 上側の「（ユーザー名）のユーザー環境変数」にある「新規...」を押します。**下側のシステム環境変数ではありません。**
5. 「変数名」に `GEMINI_API_KEY` と入力します。
6. 「変数値」に取得したAPIキーを貼り付けます。値に引用符 `"` は付けず、余分な空白・改行を入れません。
7. 既に同じ名前がある場合は「新規」ではなくその項目を「編集」します。
8. 各画面の「OK」を押して閉じます。
9. 起動中のアプリ・PowerShellを閉じます。
10. **確実に反映するため、一度Windowsからサインアウトし、サインインし直します。** 保存中の作業があれば先に保存してください。PCの再起動でも構いません。

ユーザー環境変数は、サインインし直した後も保存されます。APIキーはアプリの設定画面では入力しません。

### 5-3. PowerShellで設定する方法（任意）

画面操作の代わりに次でも登録できます。引用符内を実際のキーへ置き換えてください。

```powershell
[Environment]::SetEnvironmentVariable("GEMINI_API_KEY", "ここに取得したAPIキー", "User")
```

この方法もユーザー用の保存設定です。既に起動しているアプリやPowerShellに自動で反映されるわけではありません。設定後はサインアウト・サインインを推奨します。キーを含むコマンドは履歴に残る可能性があります。

`$env:GEMINI_API_KEY = "..."` はそのPowerShellとそこから起動するアプリだけに有効な一時設定です。デスクトップのショートカット用の恒久設定とは別です。

## 6. 起動と初回確認

1. デスクトップの「Translate Service」ショートカットをダブルクリックします。
2. 「Translate Service」という画面が開くことを確認します。
3. [ユーザーガイドの初回処理](USER_GUIDE.md#3-初めての動画を処理する)に従い、短いMP4を処理します。
4. 100%・完了になり、動画と字幕が出力されることを確認します。
5. 動画を再生し、音声と字幕を確認します。

文字起こしモデルは初回処理時にダウンロードされることがあります。インストーラー終了後も初回には時間がかかる場合があります。

**生成されたexeを直接ダブルクリックしないでください。** ショートカットは `win\run_standalone.ps1` を経由し、変換用Pythonの場所など必要な環境を設定します。exeだけ別の場所へコピーして配布する構成ではありません。プロジェクトフォルダーと仮想環境も保持します。

## 7. 次回以降の起動・設定変更

- 毎回デスクトップのショートカットから起動します。インストーラーの毎回実行は不要です。
- プロジェクトフォルダーを移動するとショートカットが古い場所を指すため起動できなくなります。移動した場合は新しい場所でインストーラーを実行し直します。
- APIキーを変えたら「ユーザー環境変数」を編集し、アプリを終了してサインアウト・サインインします。
- キーが不要になったらユーザー環境変数の `GEMINI_API_KEY` を選択し、「削除」を押します。
- 提供元でキーを無効にする操作や契約終了は、Google側で別途行います。

保存場所やバックアップ方法は[ユーザーガイド](USER_GUIDE.md#8-保存場所と不要データの整理)を参照してください。

## 8. DeepLを使う場合

1. [DeepL APIの公式案内](https://www.deepl.com/pro-api)でAPIを使える契約とキーを用意します。**現行版の送信先はAPI Free用です。API Pro用のキー・送信先切替には開発者の対応が必要です。**
2. 手順5と同じユーザー環境変数画面で、変数名を `DEEPL_API_KEY`、値をそのキーとして登録します。
3. サインアウト・サインインしてからアプリを起動します。
4. 画面の「翻訳」を `deepl` に変えます。起動時の既定は `gemini` なので毎回確認します。

PowerShellを使う場合の登録例：

```powershell
[Environment]::SetEnvironmentVariable("DEEPL_API_KEY", "ここに取得したDeepLのAPIキー", "User")
```

解除はユーザー環境変数画面で `DEEPL_API_KEY` を削除します。
