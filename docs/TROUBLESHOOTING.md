## 1. 最初にすること

1. エラーが出た画面、失敗した処理段階、Job IDを控えます。
2. 元動画・完成物・ジョブ内のデータを消さないでください。復旧や調査に使える場合があります。
3. 同じジョブを大量に再登録したり、アプリを複数起動したりしないでください。API料金や上書きが増える場合があります。
4. インストール中なら、最後のエラーを控えてから画面を閉じます。
5. 以下の症状に対応する項目を確認します。

セキュリティ機能の全面無効化、PC全体の実行ポリシー変更、データフォルダーの一括削除を解決策にしないでください。組織のPCでは管理者へ相談します。

## 3. インストールできない

### Mac：Homebrewがない

Translate ServiceのインストーラーはHomebrew自体を導入しません。[Mac手順のHomebrew導入](INSTALL_MAC.md#3-開発用ツールとhomebrewを用意する)を完了します。公式インストール後の「Next steps」の環境設定も必要です。

導入済みなのに見つからない場合はターミナルを開き直します。Apple Siliconでは通常 `/opt/homebrew`、Intelでは通常 `/usr/local` にありますが、別の場所に導入した場合は担当者へ確認してください。

### Mac：`clang was not found`／開発用ツールのエラー

ターミナルで実行します。

```bash
xcode-select --install
```

完了後にインストーラーを再実行します。既に導入済みなのに失敗する場合はmacOS更新との不整合などを担当者に調査してもらいます。アプリ生成時のエラーを控えてください。

### Mac：インストーラーやアプリがブロックされる

1. 公式プロジェクトから取得したファイルであることを確認します。
2. macOSの「システム設定」→「プライバシーとセキュリティ」に、当該アプリを開くための確認が出ていれば、表示内容と組織の規則を確認します。
3. 許可できる場合だけOSの案内に従います。OSバージョンにより画面が違うことがあります。
4. `install.command` の実行権限だけが問題なら、[Mac手順](INSTALL_MAC.md#5-インストーラーを実行する)の `bash mac/install.command` を使えます。

出所不明のファイルを許可しないでください。GatekeeperをPC全体で無効化する必要はありません。

### Windows：wingetが認識されない

[Windows手順](INSTALL_WINDOWS.md#2-app-installerとwingetを確認する)のApp Installerを導入・更新します。PowerShellを新しく開き、必要ならサインアウト・サインインして再確認します。

Microsoft Storeを利用できない場合は組織の担当者へ相談してください。

### Windows：PythonやFFmpegを入れたのに見つからない

初回インストールで「失敗」と出ても、直前に `Open a new PowerShell and run install.ps1 again` とあれば再試行の案内です。新しく追加された実行ファイルの場所が、既に開いていた画面へ反映されていない可能性があります。赤い文字だけで、PCが壊れたという意味ではありません。更新版はPythonの導入先をPATH以外からも検出します。Pythonのエラーが続く場合は次の「Pythonが複数あり対応版を検出できない」を確認します。

1. 最後のエラーを控えてから、開いているインストーラー・PowerShellを閉じます。
2. エクスプローラーで、同じ場所の `win\install.cmd` をもう一度ダブルクリックします。新しいPowerShellは自動的に起動するため、手動で開く必要は通常ありません。
3. 完了メッセージまで待ちます。具体的な表示は[Windowsの再試行手順](INSTALL_WINDOWS.md#初回に新しいpowershellを開いて再実行と出た場合)を参照してください。
4. 2回目も失敗する場合は、最後のエラーを控え、PowerShellで確認します。

```powershell
ffmpeg.exe -version
```

認識されない場合はFFmpegの導入またはPATH設定の問題です。闇雲に実行ファイルをコピーせず、インストーラーのエラーとwingetの結果を担当者に伝えます。

### Windows：Pythonが複数あり対応版を検出できない

`python --version` が3.8や3.14でも、それだけで対応Pythonがないとは判断できません。Windowsでは複数バージョンを共存できます。更新版のプロジェクトを取得し、その `win\install.cmd` を実行します。他アプリのPythonをアンインストールしないでください。

更新版は、正常な既存のアプリ用環境を再利用し、新規作成時はPython Launcher・登録情報・標準導入先・PATHからx64の対応Pythonを探します。ログの `[python]` に、使わなかった候補の理由と使える候補を表示します。

担当者へ相談する際は、PowerShellで次を1行ずつ実行し、結果を控えます。

```powershell
py -0p
py -3.12 -c "import sys; print(sys.version); print(sys.executable)"
```

`py` が認識されない場合はLauncherがないか見つからない状態です。更新版はLauncherがなくても他の場所を調べます。上記が成功した場合は、表示された `python.exe` の絶対パスを使ってインストーラーへ明示できます。

プロジェクトフォルダーをPowerShellで開いた状態の例：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\win\install.ps1 -PythonPath "C:\実際の導入先\Python312\python.exe"
```

パスは必ず実際に確認したものへ置き換えます。`.venv` 内ではなく、導入元のPythonを指定します。明示したPythonが非対応・32-bit・Tkinterなし等の場合は停止し、別の候補を黙って使うことはありません。

`No usable x64 Python...` が出た場合は、直前の診断も確認します。Tkinter・venv・ensurepipが不足した導入、壊れた実行ファイル、非標準の導入先などが原因になる場合があります。プロジェクト全体やジョブデータを削除せず担当者へ相談してください。

### Windows：スクリプト実行が拒否される

通常は `install.cmd` を使います。PowerShellから実行する場合は、プロジェクトフォルダーで次を使います。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\win\install.ps1
```

組織のグループポリシー等による拒否は、この指定で解除できるとは限りません。管理者へ相談してください。`Set-ExecutionPolicy` でPC全体の設定を変更する必要はありません。

### Python 3.14／ライブラリのビルドで失敗する

標準インストーラーが探すPythonは3.10～3.13です。3.14では依存ライブラリの導入に失敗する場合があるため使わないでください。

更新版のWindowsインストーラーは、既存の `.venv` を実行して検証します。非対応・破損した環境は別名へ退避し、対応Pythonから作り直します。Macのインストーラーはこの自動修復の対象ではありません。[開発者ガイド](DEVELOPER_GUIDE.md#3-開発環境)の環境切り分けを担当者に依頼してください。ジョブデータを消す必要はありません。

### `No module named tkinter`／`_tkinter`

Tkinterは画面表示の部品です。

- Macではインストーラーが選んだPythonと同じバージョンのTk対応が必要です。インストーラーを再実行し、`python-tk` の導入エラーがないか確認します。
- WindowsではTkinterを含むPython環境が必要です。選ばれたPythonと仮想環境を担当者に確認してもらいます。
- 別のPythonで起動しても、アプリが使う `.venv` にTkがない問題の解決にはなりません。

### ダウンロード・依存ライブラリ導入が失敗する

通信、空き容量、プロキシ、組織のネットワーク制限を確認します。初回インストールにはネット接続が必要です。最後のエラーが認証・証明書・タイムアウトのどれかを控えます。

証明書検証を無効にして続行せず、管理者へ相談します。画面が止まっているだけなら、まだダウンロード中か確認してください。

## 4. 起動できない・履歴が見えない

### Mac：アプリが開かない

1. `mac/TranslateService.app` が元のプロジェクト内にあることを確認します。
2. `source/worker` と `.venv` があることを確認します。アプリだけ移動した場合は元の構成へ戻します。
3. `source/worker/data/app-launch.log` をテキストエディットで開きます。
4. Python、Tkinter、FFmpegのエラーなら該当項目へ進みます。

インストールが不完全なら同じ場所のインストーラーを再実行します。ログがない場合はランチャーの起動前に失敗している可能性もあるため、OSの警告とアプリの場所を担当者へ伝えます。

### Windows：ショートカットから開かない

1. exeを直接開くのではなくデスクトップのショートカットを使います。
2. プロジェクトを移動していないか確認します。移動した場合は新しい場所でインストーラーを再実行してショートカットを作り直します。
3. エラー画面がすぐ閉じる場合は、PowerShellを開き、ユーザーフォルダー直下に取得した例なら次を実行します。

```powershell
cd "$HOME\ondemand_translater"
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\win\run_standalone.ps1
```

別の場所へ置いた場合は `cd` のパスを実際のプロジェクトの場所へ変えます。表示されたエラーを控えます。Windows版には、Macと同じ `app-launch.log` が必ず生成されるわけではありません。

### 更新後・起動方法変更後に履歴が空に見える

データフォルダーが変わっている可能性があります。MacではFinder起動とターミナル起動で場所が異なり、ZIPを新しい場所へ展開した場合もFinder起動時の場所が変わります。

[保存場所一覧](USER_GUIDE.md#8-保存場所と不要データの整理)と以前の起動方法を確認します。履歴を戻そうとして複数の `jobs.db` やJSONを手動で混ぜないでください。

### 起動直後に古い待機ジョブが動く

待機ジョブは保存される仕様です。不要なら一覧の該当行を選んでキャンセルします。フォルダーからJSONを直接消して取り消す方法は使いません。

## 5. 動画処理が失敗する・進まない

### 「ジョブを追加できません」

- 入力動画が実在するMP4か確認します。別形式を名前変更しただけでは使えません。
- 出力先はフォルダーです。存在し、書込みできる場所を指定します。
- SRT指定が残っていれば、対象動画に合うSRTか確認します。通常処理なら字幕欄を空にします。
- 外付けディスクやネットワーク先が切断されていないか確認します。
- 用語CSVの保存で失敗することもあります。データフォルダーへの書込み権限も確認します。

### 「エラー」、`exit code 1`

`exit code 1` は「変換プロセスが失敗した」という要約です。原因そのものではありません。[ジョブログ](#8-ログを調べる)を開き、末尾の具体的なエラーを確認します。

### APIキーがない・認証できない

1. GUIの「翻訳」が、キーを用意したサービスと一致しているか確認します。
2. `GEMINI_API_KEY`／`DEEPL_API_KEY` の名前の綴りと、余分な空白・改行がないか確認します。
3. MacのFinder起動では `launchctl setenv` を使います。再起動・ログアウト後は設定し直します。
4. Windowsは**ユーザー環境変数**を設定します。アプリを終了し、サインアウト・サインインして反映します。
5. API提供元でキーの有効性、利用できるモデル、API契約を確認します。

現行版のDeepL送信先はAPI Free用です。API Proのキーで失敗する場合、アプリ側の送信先を開発者に確認してもらいます。通常のDeepL翻訳アプリの契約とAPI契約も区別してください。

APIキーを画面やログに表示して確認する必要はありません。失敗ジョブは自動再実行されないため、設定修正後に新しいジョブを登録します。同名出力の上書きに注意してください。

### Gemini APIキーの取得画面で進めない

取得先は[Google AI StudioのAPIキー画面](https://aistudio.google.com/apikey?hl=ja)です。キー取得前に、大学名や会社名を付けた検索で別サイトの手順を探す必要はありません。

- **ログインできない／利用が制限される**：利用するアカウントと組織の規則を確認し、担当者へ相談します。個人アカウントへ無断で切り替えて組織の制限を回避しないでください。
- **プロジェクトが一覧にない**：既にGoogle Cloudを利用しているアカウントでは、既存プロジェクトのインポートが必要な場合があります。公式の[プロジェクトの説明](https://ai.google.dev/gemini-api/docs/api-key?hl=ja)を確認し、所属先で利用を許可されたプロジェクトを担当者に確認します。
- **「APIキーを作成」が押せない／権限がない**：プロジェクト管理者へ作成権限を相談します。別アカウントや新規プロジェクトを使ってよいかも担当者の判断が必要です。
- **キーの名前と値を区別できない**：名前は管理用ラベルです。アプリに設定するのはコピー操作で得られる長いキーの文字列です。確認のために他人へキーそのものを送らないでください。
- **画面がマニュアルと違う**：提供元の画面は変わります。公式日本語ガイドを参照し、判断できない場合はキーを隠した画面と操作した場所を担当者へ伝えます。

### APIの401／403／429やモデルエラー

ステータスだけで原因を断定せず、提供元のメッセージも確認します。

| 表示の例 | 主に確認するもの |
|---|---|
| 400・キーが無効 | キーの形式、リクエストに関する詳細 |
| 401・403 | キー、APIの権限、契約、地域や組織の利用制限 |
| 404・モデルがない | 現在使えるモデル。GUIからモデル名は変更できません |
| 429・quota／rate limit | 利用割り当て、料金設定、呼出し頻度。時間を置くか管理画面で確認 |
| timeout／5xx | 通信環境、提供元の障害 |

サービスのモデル・料金・上限は変わります。アプリはモデル候補の切替や分割送信を行う場合がありますが、成功や料金の一定額を保証しません。連続した再登録は避け、必要なら開発者にログを渡します。

### 英語音声生成で失敗する

翻訳が成功しても、Edge TTSの通信で失敗することがあります。ネット接続、組織のアクセス制限、サービスの障害を確認します。

完成した英語SRTが残っていれば、元動画と英語SRTで新しいジョブを登録し、文字起こし・翻訳を省略できます。再開用ファイルを先に別の場所へコピーして保存すると安全です。

### 文字起こしで長く止まる／メモリ不足

初回モデル取得、長い音声、高精度モデルで時間がかかることがあります。ログの更新とOSのアクティビティモニタ（Mac）／タスク マネージャー（Windows）でCPU・メモリ・ディスクを確認します。

- 進捗率だけで停止と判断しないでください。
- 不要な他のアプリを閉じます。
- 問題を再現できる短い動画を `fast` で試します。
- PCを電源につなぎ、スリープ・通信切断を避けます。

一定時間で必ず完了するという基準はありません。強制終了を繰り返さず、処理段階とログ更新時刻を担当者へ伝えます。

### キャンセル・終了後も処理が残るように見える

停止要求は変換の親プロセスに送られます。FFmpeg等の子処理が即時にすべて終了するとは限りません。データ削除や二重起動を避けて担当者に相談してください。

担当者は対象のPIDとジョブを確認して対応します。全Python・全FFmpegプロセスを名前だけで一括停止する方法は使いません。他のアプリの処理を止める危険があります。

## 6. 出力・字幕・用語の問題

### 「完了ファイルを開く」で再生されない

Finder／エクスプローラーで完成動画を選択する動作が正常です。選択された動画をダブルクリックして再生します。

「未完了」が出る場合は完了済みの行を選択します。「出力なし」の場合は完成動画を移動・削除していないか確認します。履歴のパスは、出力を後から移動しても自動更新されません。

### 字幕が表示されない

1. 再生ソフトの字幕メニューから英語字幕トラックを有効にします。
2. 別の字幕対応プレーヤーで確認します。
3. 必要なら同じ出力先の英語SRTをプレーヤーで読み込みます。

GUIの字幕は通常「埋め込み」で、映像に文字を固定する焼き込みではありません。ただし埋め込み処理が失敗した場合、パイプラインは焼き込み動画へのフォールバックを試すため、実際の結果とログも確認します。

### 日本語字幕が空

英語SRTだけを入力すると、文字起こしをスキップするため日本語字幕が空になる場合があります。日本語SRTも入力するか、字幕なしで元動画から処理してください。

出力される日本語SRTは `jp.srt` 相当の文字起こし結果です。内部で整形した `jp_clean.srt` と同一とは限りません。

### 誤訳・専門用語の誤認識・音声時刻のずれ

- 元音声が聞き取りやすいか、対象字幕が別動画のものではないか確認します。
- 短い区間で `balanced` と `high-accuracy` を比較します。精度向上を保証するものではありません。
- 専門用語は文字起こし用のヒントで、翻訳結果の固定辞書ではありません。プロンプト長にも上限があります。
- 英語SRTを人が確認・修正し、元動画とそのSRTを新しいジョブへ登録する方法があります。
- 標準の音声配置は重なりを避けるため後続音声と字幕を遅らせる場合があります。CLI向けの時刻設定は開発者に相談します。

### CSVが文字化けする／読めない

UTF-8（BOM付きも可）のCSVを使います。表計算ソフトなら「CSV UTF-8」で保存します。1列・1行1用語を推奨します。「CSV読込」は追加であって置換ではありません。

追加用語の削除・保存の動作は[ユーザーガイド](USER_GUIDE.md#7-専門用語を登録する)を確認してください。

### 既定の工学用語が表示されない

特にWindowsの生成済みGUIでは、ビルド内に既定CSVがなく、一覧が空になる場合があります。プロジェクト内の `source/worker/lecture_poc/prompts/engineering_terms.csv` を「CSV読込」から読み込む方法で利用できます。読込後の一覧を確認してください。

CSVが見つからない場合はプロジェクト全体を取得できているか確認します。配布・ビルドの恒久対応は開発者に依頼します。

## 7. 保存・削除・容量の問題

### 保存できない・ディスク不足

出力先だけでなく、データフォルダーのあるディスクにも空き容量が必要です。ジョブ登録時には入力動画をコピーし、処理中に音声や複数の動画を作ります。

書込み可能なPC内フォルダーで短い動画を試します。クラウド同期、外付けディスクの切断、ファイルを開いている他アプリ、権限を確認します。エラー時の作業データは、原因が分かるまで保持します。

### 「ジョブ内の動画を削除できませんでした」

完成物の保存後、作業用動画の削除で失敗した状態です。出力先には成果物がある可能性がありますが、ジョブはエラーになります。

1. エラーメッセージの対象パスを控えます。
2. 中間動画を開いている再生ソフト、ファイルをロックするソフト、書込み権限を確認します。
3. 原因解消後、正常な出力を確認してから担当者に残存動画の整理を依頼します。

このエラーだけのために翻訳全体を再実行すると、追加のAPI利用や上書きが発生する場合があります。

### 動画がデータフォルダーに残る

次の場合は仕様上残ることがあります。

- まだ待機中・処理中
- エラー・キャンセル済み
- 自動削除機能導入前に完了したジョブ
- そのフォルダー内を出力先として指定した完成動画
- 別のCLI実行や旧構成の生成物

現在のGUIジョブが正常完了した後は、そのジョブ内の指定出力以外の動画を削除します。別のジョブや旧フォルダーを一括で掃除する機能ではありません。

### 動画は消えたが容量が減らない

音声・字幕・本文・ログは残ります。モデルのキャッシュもジョブ外にある場合があります。安全な整理手順は[ユーザーガイド](USER_GUIDE.md#8-保存場所と不要データの整理)を確認します。ゴミ箱へ移しただけでは空き容量が増えない場合もありますが、バックアップを確認する前にゴミ箱を空にしないでください。

## 8. ログを調べる

### 場所

データフォルダーの場所は[ユーザーガイド](USER_GUIDE.md#8-保存場所と不要データの整理)を確認します。Job IDはGUI一覧の左側の長い識別番号です。

| ファイル | 分かること |
|---|---|
| Macの `source/worker/data/app-launch.log` | Finder起動時のエラー。起動のたびに追記 |
| データフォルダーの `logs/<Job ID>.log` | 変換コマンド、標準出力・エラー。原因調査の第一候補 |
| `jobs/<Job ID>/pipeline.log` | `START`、`DONE`、`FAIL` など各工程の記録 |
| `jobs/<Job ID>/status.json` | ジョブ状態と `error_message`。コピー・削除エラーはここも確認 |

### 読み方

1. 対象のJob IDと同じ名前のログをテキストエディット／メモ帳で開きます。
2. 末尾から読みます。
3. 最後の処理段階と、具体的なエラーメッセージを探します。
4. 問い合わせ用には、必要な箇所だけ抜き出します。

ログを編集・削除して直そうとしないでください。文字化けする場合はUTF-8で開けるエディターを使います。

ログには自分の名前が入ったパス、字幕内容等が含まれる可能性があります。秘密のマスキング処理があっても、共有前の確認は必要です。**APIキー、トークン、個人情報、機密の講義本文を隠してください。**

